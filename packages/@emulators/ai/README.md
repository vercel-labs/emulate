# @emulators/ai

Deterministic OpenAI Responses and Chat Completions emulation for local development and CI. Replies are scripted by rules, not generated by a model, so the same request returns the same answer on every run. Streams, structured output, tool calls, reasoning, refusals, stored responses, failures, and stream faults are all available on demand.

Part of [emulate](https://github.com/vercel-labs/emulate) — local drop-in replacement services for CI and no-network sandboxes.

## Install

```bash
npm install @emulators/ai
```

Run it through the CLI:

```bash
npx emulate start --service ai --port 4014
```

A single selected service otherwise uses the base port, normally 4000. In an all-services run, `ai` listens on port 4014.

## Base URL

Point clients at `http://localhost:4014/v1`. Any path prefix works, such as `/v1` or `/api/v1`; the format is selected from the end of the request path. API keys are accepted but never required, stored, or logged. Every generation response carries a deterministic request id in the `x-request-id` header.

```typescript
import OpenAI from "openai";

const openai = new OpenAI({
  baseURL: "http://localhost:4014/v1",
  apiKey: "test",
});
```

The Vercel AI SDK uses the same base URL through its OpenAI provider:

```typescript
import { createOpenAI } from "@ai-sdk/openai";

const openai = createOpenAI({
  baseURL: "http://localhost:4014/v1",
  apiKey: "test",
});

openai("gpt-x");
openai.chat("gpt-x");
```

`openai('gpt-x')` posts to `/v1/responses`, and `openai.chat('gpt-x')` posts to `/v1/chat/completions`.

`@ai-sdk/openai-compatible` works in Chat mode with the same base URL. Vercel AI Gateway's OpenAI-compatible `/v1` shape works too. Any model id is accepted and echoed back. `createOpenAICompatible` sends `json_object` without a schema unless the provider sets `supportsStructuredOutputs: true`, so `generateObject` against the default `{}` reply fails its schema check: set `supportsStructuredOutputs: true`, or script the object with an `object` reply rule. The private `@ai-sdk/gateway` protocol is not supported.

## Endpoints

### Data

- `POST /v1/chat/completions` — Chat Completions, unary or streamed
- `POST /v1/responses` — Responses, unary or streamed
- `GET /v1/responses/{id}` — retrieve a stored response
- `DELETE /v1/responses/{id}` — delete a stored response
- `GET /v1/models` — list configured and previously requested model ids

An unsupported data path returns the native 404 naming the supported paths.

### Control

- `GET /_ai/calls` — recorded calls
- `DELETE /_ai/calls` — clear the call record
- `GET /_ai/rules` — active rules with remaining budgets
- `PUT /_ai/rules` — replace the active rules without restarting
- `POST /_ai/reset` — restore seeded rules and budgets, and clear calls and stored responses
- `GET /` — read-only inspector with Calls and Rules tabs

`GET /_ai/calls` returns a bare JSON array, oldest first. `DELETE /_ai/calls` returns `{ "deleted": <count> }`. `GET /_ai/rules` and `PUT /_ai/rules` return `{ "rules": [...], "strict": <bool>, "timing": {...}, "random": { "seed": <number> }, "models": [...] }` with each rule's `remaining` budget (`null` means unlimited), in the shape `PUT` accepts. `POST /_ai/reset` returns `{ "reset": true }`.

Control routes and the inspector refuse cross-origin browser requests, reads included. Requests without an `Origin` header, such as curl or a test, are accepted. Data routes accept SDK and server calls, which send no `Origin`, and browser pages served on this machine (`localhost`, `*.localhost`, `127.0.0.1`, `[::1]`); a page on any other website gets 403. Startup warns when the service listens beyond loopback.

## Seed Configuration

```yaml
ai:
  strict: false
  timing:
    ttftMs: 0
    chunkDelayMs: 0
  random:
    seed: 7
  models:
    - gpt-x
  rules:
    - id: weather-call
      match:
        textContains: weather
        tool: get_weather
        hasToolResult: false
      times: 1
      reply:
        - type: tool_call
          name: get_weather
          arguments:
            city: Paris

    - id: weather-result
      match:
        hasToolResult: true
      reply:
        - type: text
          text: The temperature in Paris is 20 C.

    - id: rate-limit-once
      match:
        textContains: retry
      times: 1
      error:
        status: 429
        message: Injected rate limit. Retry this request.
        headers:
          retry-after: "1"
```

Rules are evaluated in order and the first match wins. Every supplied matcher must hold. `times` limits how many times a rule can fire. An unknown configuration key fails at startup with its path. `PUT /_ai/rules` accepts the config fields of the seed `ai` block (`rules`, plus optional `strict`, `timing`, `random`, and `models`); `port` and `baseUrl` are ignored. A body with only `rules` resets the other fields to their defaults. Every replacement restores each rule's full `times` budget.

## Rules

Matchers:

- `model` — model id, with `*` wildcards
- `format` — `openai-chat` or `openai-responses`
- `stream` — boolean
- `textContains` — case-sensitive text in the latest user instruction, excluding tool results
- `tool` — a declared tool name, with `*` wildcards
- `hasToolResult` — whether the current continuation carries a tool result
- `file` — `true` for any attachment, including one returned inside a tool result, or a media-type glob such as `application/pdf`

Reply events:

- `text` — `{ type: text, text }`
- `object` — `{ type: object, value }`, sent as JSON text
- `tool_call` — `{ type: tool_call, name, arguments }`; `arguments` must be a JSON object, and a string is rejected at startup and on `PUT /_ai/rules`
- `reasoning` — `{ type: reasoning, text }`, Responses only
- `refusal` — `{ type: refusal, text }`, native refusal shape

A rule has one of `reply`, `variants`, or `error`. With `variants`, the seed in `ai.random.seed` shuffles the variants per rule and each rule's own matches walk that order in a cycle, so the same seed replays the same sequence and every variant appears once per cycle. A variant holds either `reply` or `error`, and SDK retries spend the next variant. It may also override `finish`, `timing`, and `fault`, with the rule-level values as defaults. Reply rules may also set `finish` (`stop`, `tool_calls`, `length`, `refusal`, or `content_filter`), `timing`, or `fault`, and `fault` also requires `match.stream: true`. A fault disconnects or stalls a stream after a counted number of content chunks.

## Defaults

With no matching rule, the service:

- echoes the latest user text
- returns a deterministic, schema-valid object when a schema was requested
- returns `{}` for JSON mode without a schema
- returns a generated call when the request forces a tool
- acknowledges a tool result or an attachment-only request
- accepts and echoes any model id

Set `strict: true` to turn every unmatched request into a native 400 naming the model and tools and including the missing rule as YAML and JSON.

## State and Privacy

Responses are stored by default so multi-turn sessions and item references resolve. Set `store: false` to skip storage. Unknown `previous_response_id` and item references are treated as empty context, so a request still succeeds. A function call with no matching `function_call_output` returns OpenAI's 400, `No tool output found for function call <id>.`, unless the history it refers to is missing.

Every generation request is recorded with its format, model, `matched`, normalized prompt and tool arguments, and outcome. `matched` is `{ "id": "<rule id>", "remaining": <budget left or null>, "rule": <the rule as it was when it answered> }` for a rule, `{ "default": "<kind>" }` when a default answered, and `null` when strict mode rejected the request. The last 500 calls are kept. Stored responses are capped at the most recent 1000; older ones are evicted. Keys, auth headers, and file bytes are never recorded. Attachment metadata records the name, media type, size, and hash only.

## Limits

Result-changing features outside this version return a native 400 naming the feature: hosted tools, custom tools, allowed tool choice, background mode, the Conversations API, multiple candidates, audio input, audio output, and legacy functions.

Paths with no route return the native 404 naming the supported paths: Anthropic Messages, Gemini, embeddings, image generation, file uploads, input item listing, token counting, and response cancellation.

Accepted and ignored, with no effect on replies: stop sequences, max output token settings, OpenRouter `reasoning` fields, and unknown optional fields. Replies are never truncated, and reply text is sent as written with no templating, so use a rule with `finish: length` to test truncation.
