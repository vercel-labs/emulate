# Microsoft Graph

Stateful Microsoft Graph emulation for app-only integrations: tenant-scoped Entra client credentials tokens, users with OData queries, guest invitations with redeemable links, directory role definitions and assignments, groups, organization, deleted items, JSON `$batch`, a simulator, an event log, and an inspector.

## Start

```bash
npx emulate --service graph
```

When Graph is the only enabled service, it starts on `http://localhost:4000`. When all services are started, it uses `http://localhost:4021`.

## URL Mapping

| Real URL | Emulator URL |
|----------|--------------|
| `https://login.microsoftonline.com/{tenantId}/oauth2/v2.0/token` | `$GRAPH_EMULATOR_URL/{tenantId}/oauth2/v2.0/token` |
| `https://graph.microsoft.com/v1.0/...` | `$GRAPH_EMULATOR_URL/v1.0/...` |

## Authentication

```bash
curl -X POST http://localhost:4000/00000000-0000-4000-8000-00000000c0de/oauth2/v2.0/token \
  -d grant_type=client_credentials -d scope=https://graph.microsoft.com/.default \
  -d client_id=00000000-0000-4000-8000-0000000000a9 -d client_secret=test_emulate_graph_client_secret
```

The tenant segment accepts a tenant id or a verified domain. The JWT carries `tid`, `appid`, and `roles`; every request only sees its tenant. Wrong secrets return `invalid_client`, unknown tenants `AADSTS90002`, and apps seeded with `tenant_ids` get `unauthorized_client` elsewhere. Apps seeded with a `permissions` list are limited to those application permissions: routes outside it return 403 `Authorization_RequestDenied` with "Insufficient privileges to complete the operation.", which is the message clients test for.

## Conventions

- Collections return `@odata.context`, `value`, `@odata.count` when `$count=true`, and `@odata.nextLink` carrying `$skiptoken` when more pages exist. Default page size is 100, maximum 999.
- `$filter` supports `eq`, `ne`, `gt`, `ge`, `lt`, `le`, `and`, `or`, `not`, `in (...)`, `startsWith()`, `endsWith()`, `contains()`, plus `$select`, `$orderby`, and `$search="field:value"`.
- Errors are `{ error: { code, message, innerError: { date, request-id, client-request-id } } }`: `Request_ResourceNotFound` (404), `Request_BadRequest` (400), `Request_UnsupportedQuery` (400), `Authorization_RequestDenied` (403), `InvalidAuthenticationToken` (401).
- Writes return 201 with the entity, updates and deletes return 204.

## Users

- `GET /v1.0/users` - filterable on any user property, for example `mail in ('a@x.com','b@x.com')`, `accountEnabled eq false`, `userType eq 'Guest' and startsWith(mail, 'nora')`
- `POST /v1.0/users` - `accountEnabled`, `displayName`, `mailNickname`, `userPrincipalName`, `passwordProfile.password` required
- `GET /v1.0/users/{id or userPrincipalName}` with `$select`, `PATCH /v1.0/users/{id}` (`accountEnabled`, `displayName`, `givenName`, `surname`, `mail`, `jobTitle`, `mobilePhone`, `officeLocation`, `preferredLanguage`, `department`, `businessPhones`, `otherMails`, `userPrincipalName`; unknown properties return 400), `DELETE /v1.0/users/{id}` (soft delete)
- `GET /v1.0/users/{id}/memberOf`, `GET /v1.0/users/{id}/transitiveMemberOf` (groups and activated directory roles)
- `GET /v1.0/directory/deletedItems/microsoft.graph.user`, `POST /v1.0/directory/deletedItems/{id}/restore`

User objects carry `id`, `displayName`, `givenName`, `surname`, `mail`, `userPrincipalName`, `mailNickname`, `jobTitle`, `mobilePhone`, `officeLocation`, `preferredLanguage`, `businessPhones`, `accountEnabled`, `userType`, `externalUserState`, `department`, `companyName`, `otherMails`, `proxyAddresses`, `identities`, and `createdDateTime`.

## Invitations

`POST /v1.0/invitations` with `invitedUserEmailAddress`, `inviteRedirectUrl`, optional `invitedUserDisplayName`, `sendInvitationMessage`, `invitedUserMessageInfo`, `resetRedemption`. It creates a Guest user (`mail` set to the address, `userPrincipalName` in the `name_domain.com#EXT#@tenant.onmicrosoft.com` form, `externalUserState: PendingAcceptance`, `accountEnabled: true`) and returns the invitation with `invitedUser { id, userPrincipalName }` and an `inviteRedeemUrl`. Inviting the same address again reuses the guest. Opening the redeem link or calling `POST /_graph/simulate/accept-invitation` with `invitationId`, `email`, or `userId` marks the user `Accepted`.

## Role Assignments

- `GET /v1.0/roleManagement/directory/roleAssignments` (filter `principalId eq '...'` or `roleDefinitionId eq '...'`), `POST` with `principalId`, `roleDefinitionId` (role id or template id), `directoryScopeId` (`/`): 201 with `{ id, principalId, roleDefinitionId, directoryScopeId }`; a duplicate returns 400 "A conflicting object with one or more of the specified property values is present in the directory."; unknown principals or roles return 404
- `GET|DELETE /v1.0/roleManagement/directory/roleAssignments/{id}`
- `GET /v1.0/roleManagement/directory/roleDefinitions`, `GET .../roleDefinitions/{id}`, `GET /v1.0/directoryRoles`, `GET /v1.0/directoryRoles/{id}/members`

Seeded template ids include Global Administrator `62e90394-69f5-4237-9190-012177145e10`, Security Administrator `194ae4cb-b126-40b2-bd5b-6091b380977d`, Privileged Authentication Administrator `7be44c8a-adaf-4e2a-84d6-ab2649e08a13`, Security Reader, Security Operator, Privileged Role Administrator, User Administrator, Helpdesk Administrator, Application Administrator, Exchange Administrator, Global Reader, and Directory Readers.

## Groups and Organization

- `GET|POST /v1.0/groups`, `GET|PATCH|DELETE /v1.0/groups/{id}`, `GET /v1.0/groups/{id}/members`, `POST /v1.0/groups/{id}/members/$ref` (`{ "@odata.id": ".../directoryObjects/{userId}" }`), `DELETE /v1.0/groups/{id}/members/{userId}/$ref`
- `GET /v1.0/organization`, `GET /v1.0/servicePrincipals`, `GET /v1.0/me` (400 for app-only tokens, as on Graph)

## $batch

`POST /v1.0/$batch` with `{ requests: [{ id, method, url, headers, body, dependsOn }] }` (at most 20). Each request runs against the emulator with the caller's token and returns `{ id, status, headers, body }`; requests whose `dependsOn` failed return 424. This is how bulk invite, suspend, reactivate, and role assignment flows are exercised.

## Simulator, Events, Inspector

- `GET /_graph/redeem/{code}` - accept an invitation through its redeem link
- `POST /_graph/simulate/accept-invitation` - `invitationId`, `email`, or `userId`
- `POST /_graph/simulate/sign-in` - `userId`, `userPrincipalName`, or `mail`; disabled accounts return 403 `AADSTS50057`
- `GET /_graph/events?type=invitation.created&tenant=` - JSON event log (`token.issued`, `user.*`, `invitation.*`, `role_assignment.*`, `group.created`, `batch.executed`); `DELETE` clears it
- `GET /` - inspector tabs: users, role assignments, invitations, groups, tenants, events, auth

Users accept explicit `id` values and `roles` by display name, role id, or template id. Guests without a `userPrincipalName` get the `#EXT#` form automatically. Seeding is idempotent by id, UPN, or email.

## Limits

Delegated flows and `/me`, mail, calendar, Teams, SharePoint, device management, delta queries, change notifications, and PIM eligibility schedules are not implemented.
