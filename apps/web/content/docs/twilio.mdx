Stateful Twilio REST emulation with seeded accounts, Auth Tokens, API keys, incoming phone numbers, Programmable Messaging, Messaging Services, Verify, basic Voice calls, Conversations REST resources, SendGrid Mail Send, signed webhooks, local simulator routes, and an inspector.

## Start

```bash
npx emulate --service twilio
```

When Twilio is the only enabled service, it starts on `http://localhost:4000`. When all services are started, it uses `http://localhost:4013`.


## URL Mapping

| Real Twilio URL | Emulator URL |
|-----------------|--------------|
| `https://api.twilio.com/2010-04-01/...` | `$TWILIO_EMULATOR_URL/2010-04-01/...` |
| `https://messaging.twilio.com/v1/...` | `$TWILIO_EMULATOR_URL/messaging/v1/...` |
| `https://verify.twilio.com/v2/...` | `$TWILIO_EMULATOR_URL/verify/v2/...` |
| `https://conversations.twilio.com/v1/...` | `$TWILIO_EMULATOR_URL/conversations/v1/...` |
| `https://api.sendgrid.com/v3/mail/send` | `$TWILIO_EMULATOR_URL/v3/mail/send` |

The official Node SDK builds absolute Twilio product URLs. In SDK tests, use a custom request client that rewrites those hosts to the emulator prefixes above.

Only an `active` account can send messages or place calls. Set the seeded account `status` to `suspended` or `closed`, or update it with `POST /2010-04-01/Accounts/{AccountSid}.json` and `Status`, to test the failure: message and call creation return HTTP 401 with error `20005`, "Account not active". Set the status back to `active` to restore them.

## SendGrid Mail Send

SendGrid is a Twilio product with its own host, `api.sendgrid.com`, so the Twilio emulator serves its Mail Send route at the root: `https://api.sendgrid.com/v3/mail/send` maps to `$TWILIO_EMULATOR_URL/v3/mail/send`.

- `POST /v3/mail/send` - send email with a SendGrid v3 request body

Requests use `Authorization: Bearer <API key>`. The seeded key is `SG.emulate_local_key.twilio_test_sendgrid_api_key`. Add keys under `twilio.sendgrid.api_keys` with `key`, optional `name`, and optional `scopes`. A key with `scopes` must include `mail.send`. A missing or unknown key returns `401`, and a key without `mail.send` returns `403`.

An accepted request returns `202` with an empty body and an `X-Message-Id` header. The emulator stores the original request body with the message ID, sender, and every `to`, `cc`, and `bcc` recipient in the `twilio.sendgrid_messages` store collection, and lists it on the inspector's SendGrid tab. Invalid requests return `400` with every problem in SendGrid's `errors` array of `message`, `field`, and `help` objects. The checks cover the sender, personalizations and their 1,000-recipient limit, duplicate recipients, subjects, `text/plain` before `text/html` content order, attachments, headers, categories, `reply_to` and `reply_to_list`, `send_at`, and settings types. Set `mail_settings.sandbox_mode.enable` to `true` to validate a request without storing it; the response is an empty `200`.

Templates are not rendered. A request with `template_id` may omit `content` and `subject`, and the template ID and `dynamic_template_data` are stored as sent. Nothing is delivered or scheduled.

With the official Node packages, set the emulator URL after `setApiKey`, which resets the base URL to `api.sendgrid.com`:

```typescript
import client from "@sendgrid/client";
import mail from "@sendgrid/mail";

mail.setClient(client);
mail.setApiKey("SG.emulate_local_key.twilio_test_sendgrid_api_key");
client.setDefaultRequest("baseUrl", "http://localhost:4000/");

await mail.send({
  from: "reception@example.com",
  to: "guest@example.com",
  subject: "Your invitation",
  text: "Welcome",
});
```

## SMS And OTP Testing

The seeded Verify Service uses code `123456`, so most local OTP tests can start a verification through the normal Verify API and submit that code. Tests that need to read the current local code can use the authenticated helper route:

```bash
curl -u "$TWILIO_ACCOUNT_SID:$TWILIO_AUTH_TOKEN" \
  "http://localhost:4000/_twilio/simulate/verification-code?To=%2B15550002222&ServiceSid=$TWILIO_VERIFY_SERVICE_SID"
```

The helper returns the latest local verification for that phone number, including `verification_sid`, `status`, `attempts`, and `code`. It is local-only test support, not a production Twilio API. The Verify inspector also shows each attempted code.

For inbound SMS, configure a phone number `sms_url`, then call `POST /_twilio/simulate/inbound-message` with `To`, `From`, and `Body`. If the destination number is assigned to a Messaging Service with `inbound_request_url`, the simulator sends the inbound webhook there and includes `MessagingServiceSid`; otherwise it uses the phone number `sms_url`. For outbound delivery transitions, create a message with `StatusCallback`, then call `POST /_twilio/simulate/message-status`.

## Seed Config

```yaml
twilio:
  account:
    sid: AC00000000000000000000000000000000
    auth_token: twilio_test_auth_token
    friendly_name: Local Twilio Account
  api_keys:
    - sid: SK00000000000000000000000000000000
      secret: twilio_test_api_secret
      friendly_name: Local API Key
  phone_numbers:
    - phone_number: "+15551234567"
      friendly_name: Local SMS and Voice Number
      sms_url: http://localhost:3000/api/twilio/sms
      voice_url: http://localhost:3000/api/twilio/voice
  messaging_services:
    - friendly_name: Local Messaging Service
      phone_numbers: ["+15551234567"]
  verify_services:
    - friendly_name: Local Verify Service
      code: "123456"
      default_channel: sms
  conversations:
    services:
      - friendly_name: Local Conversations
  sendgrid:
    api_keys:
      - key: SG.emulate_local_key.twilio_test_sendgrid_api_key
        name: Local SendGrid API Key
```

## Inspector

Open `GET /` in the Twilio emulator to inspect messages, Verify attempts, calls, Conversations, SendGrid email, phone numbers, services, credentials, and webhook deliveries.

## Current Limits

No real SMS, MMS, WhatsApp, email, voice, carrier, compliance, billing, Studio, Flex, TaskRouter, Video, Sync, Segment, Conversations SDK websocket behavior, or complete TwiML interpreter behavior is implemented. SendGrid APIs other than Mail Send, template rendering, scheduled sends, and verified sender checks are not emulated.
