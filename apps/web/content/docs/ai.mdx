Deterministic emulation for OpenAI Responses, OpenAI Chat Completions, and Anthropic Messages. Rules and deterministic defaults decide every reply, so the same config and request sequence repeat text, structured output, tool calls, reasoning, refusals, errors, and stream timing identically with no API key or network access.

```bash
npx emulate start --service ai --port 4014
```

Examples on this page use port `4014`, the default port when all services start together. Starting `ai` alone without `--port` uses `EMULATE_PORT`, `PORT`, or `4000`.

## Clients

Point OpenAI clients at `http://localhost:4014/v1` and the Anthropic SDK at `http://localhost:4014`. Any API key and any model id work, including `provider/model` slugs, and replies echo the requested model.

```typescript
import OpenAI from "openai";
import Anthropic from "@anthropic-ai/sdk";
import { createOpenAI } from "@ai-sdk/openai";

const client = new OpenAI({ apiKey: "test", baseURL: "http://localhost:4014/v1" });
const anthropic = new Anthropic({ apiKey: "test", baseURL: "http://localhost:4014" });

const openai = createOpenAI({ apiKey: "test", baseURL: "http://localhost:4014/v1" });
openai("anthropic/claude-sonnet-5"); // OpenAI Responses
openai.chat("anthropic/claude-sonnet-5"); // OpenAI Chat Completions
```

- The Anthropic SDK appends `/v1/messages`, so omit `/v1` from its `baseURL`.
- `@ai-sdk/openai-compatible` uses Chat Completions. Set `supportsStructuredOutputs: true` for `generateObject`; otherwise it sends `json_object` without a schema and the default `{}` reply fails validation.
- To replace Vercel AI Gateway, point your OpenAI-compatible client at `http://localhost:4014/v1` instead of `https://ai-gateway.vercel.sh/v1`, or set `OPENAI_BASE_URL`. The private `@ai-sdk/gateway` protocol is not supported.
- The emulator never validates, stores, or logs API keys, though most SDKs require a placeholder string.
- Every generation response includes a deterministic request id header: `x-request-id` on OpenAI routes and `request-id` on Anthropic Messages.

## Routes

The emulator reads the wire format from the end of the path, so any prefix works (`/v1`, `/api/v1`).

| Method   | Path                   | Behavior                                                              |
| -------- | ---------------------- | --------------------------------------------------------------------- |
| `POST`   | `.../responses`        | OpenAI Responses, unary and streamed                                  |
| `POST`   | `.../chat/completions` | OpenAI Chat Completions, unary and streamed                           |
| `POST`   | `.../messages`         | Anthropic Messages, unary and streamed                                |
| `GET`    | `.../responses/:id`    | Retrieve a stored response                                            |
| `DELETE` | `.../responses/:id`    | Delete a stored response                                              |
| `GET`    | `.../models`           | List configured and previously requested models in OpenAI's list form |
| `GET`    | `/`                    | Read-only inspector                                                   |

Unsupported paths default to a native OpenAI 404 naming the supported paths.

### Anthropic Messages

`POST .../messages` implements Anthropic's Messages wire format. Match `format: anthropic-messages` in a rule to target this route alone.

| Area              | Behavior                                                                                                             |
| ----------------- | -------------------------------------------------------------------------------------------------------------------- |
| Required fields   | `model`, `messages`, and a positive integer `max_tokens`; `system` is top-level                                      |
| Content blocks    | `text`, `image`, `document`, `search_result`, `tool_use`, `tool_result`, `thinking`, `redacted_thinking`             |
| URL sources       | `http:` or `https:` URLs for image and document blocks                                                               |
| Base64 media      | Images: `image/jpeg`, `image/png`, `image/gif`, `image/webp`; documents: `application/pdf`                           |
| Tools             | Client tools accept optional `input_schema`; hosted tool types return 400                                            |
| Structured output | Read from `output_config.format` (`type: "json_schema"`) and returned as a `text` block holding JSON                 |
| `stop_reason`     | `end_turn`, `tool_use`, `max_tokens`, `stop_sequence`, or `refusal` (`content_filter` also maps to `refusal`)        |
| Stream events     | `message_start`, `content_block_start`, `content_block_delta`, `content_block_stop`, `message_delta`, `message_stop` |
| Tool streaming    | Tool arguments stream as `input_json_delta` pieces of partial JSON                                                   |

Because `input_schema` is optional on client tools, Anthropic-defined client tools such as bash, text editor, computer use, and memory work by name. Hosted server tool types (`web_search_*`, `web_fetch_*`, `code_execution_*`, `tool_search_tool_*`, `mcp_toolset`) return 400.

Errors use Anthropic's envelope and error types (`invalid_request_error`, `authentication_error`, `permission_error`, `not_found_error`, `request_too_large`, `rate_limit_error`, `api_error`, `overloaded_error`), and validation errors start with the failing field:

```json
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "max_tokens: Expected a number."
  },
  "request_id": "req_1"
}
```

Unsupported paths under `.../messages` (such as `count_tokens`), or any unsupported data path sent with an `anthropic-version` header, return `not_found_error` in this envelope.

## Rules

Save rules under `ai` in `emulate.config.yaml` (or pass `--seed <file>`), or replace them at runtime with `PUT /_ai/rules`. Rules are checked in order and the first match answers.

```yaml
ai:
  rules:
    - id: weather-call
      match:
        textContains: weather
        tool: get_weather
        hasToolResult: false
      times: 1
      reply:
        - type: tool_call
          name: get_weather
          arguments:
            city: Paris

    - id: weather-result
      match:
        hasToolResult: true
      reply:
        - type: text
          text: The temperature in Paris is 20 C.
```

In a project config with a `services:` map, put the seed under `services.<name>.seed`. A top-level `ai:` block starts a second service named `ai`.

```yaml
services:
  llm:
    emulator: ai
    seed:
      rules:
        - id: weather
          match: { textContains: weather }
          reply: [{ type: text, text: Sunny }]
```

### Rule fields

| Field      | Purpose                                                        |
| ---------- | -------------------------------------------------------------- |
| `id`       | Names the rule in the call record, inspector, and `/_ai/rules` |
| `match`    | Request conditions; omit to match every request                |
| `times`    | Maximum matches before skipping; omit for unlimited            |
| `reply`    | Ordered list of reply events                                   |
| `variants` | Multiple reply or error bodies cycled per call                 |
| `finish`   | Overrides the finish reason (default for variants)             |
| `error`    | Returns an HTTP error instead of a reply                       |
| `fault`    | Stalls or disconnects a stream (default for variants)          |
| `timing`   | Per-rule `ttftMs` and `chunkDelayMs` (default for variants)    |

- Every rule sets exactly one of `reply`, `variants`, or `error`. `finish`, `timing`, and `fault` apply only to `reply` and `variants`.
- `times` is spent on every match, including errors, faults, and SDK retries. `POST /_ai/reset` and `PUT /_ai/rules` restore full budgets.

### Matching

Every condition in `match` must hold.

| Matcher         | Matches when                                                                                      |
| --------------- | ------------------------------------------------------------------------------------------------- |
| `model`         | Model id matches (`*` wildcards allowed)                                                          |
| `format`        | Wire format is `openai-chat`, `openai-responses`, or `anthropic-messages`                         |
| `stream`        | Request is or is not streaming                                                                    |
| `textContains`  | Latest user text contains the string (case-sensitive, ignores tool results)                       |
| `tool`          | Request declares a matching tool (`*` wildcards allowed)                                          |
| `hasToolResult` | Current turn does or does not carry a tool result                                                 |
| `file`          | `true` for any attachment (including inside tool results), or a media-type glob such as `image/*` |

### Replies

`reply` is an ordered list of events. The emulator adds ids, usage estimates, and format-specific terminal events.

| Event       | Fields                             | Output                                                                                        |
| ----------- | ---------------------------------- | --------------------------------------------------------------------------------------------- |
| `text`      | `text`                             | Assistant text                                                                                |
| `object`    | `value`                            | JSON text for structured output                                                               |
| `tool_call` | `name`, `arguments`, optional `id` | Tool call (`arguments` must be a JSON object; id generated if omitted)                        |
| `reasoning` | `text`                             | Reasoning summary in Responses; signed `thinking` block in Messages; token count only in Chat |
| `refusal`   | `text`                             | Refusal in the format's native shape                                                          |

Passing a JSON string for `tool_call.arguments` fails validation at startup and on `PUT /_ai/rules`.

#### Finish reasons

Without `finish`, a reply containing a tool call ends with `tool_calls`, a refusal with no tool call is recorded as `refusal`, and anything else ends with `stop`.

| `finish` value   | Chat Completions                                | Responses                                     | Messages                    |
| ---------------- | ----------------------------------------------- | --------------------------------------------- | --------------------------- |
| `stop`           | `finish_reason: "stop"`                         | `status: "completed"`                         | `stop_reason: "end_turn"`   |
| `tool_calls`     | `finish_reason: "tool_calls"`                   | `status: "completed"`                         | `stop_reason: "tool_use"`   |
| `length`         | `finish_reason: "length"`                       | `status: "incomplete"`                        | `stop_reason: "max_tokens"` |
| `content_filter` | `finish_reason: "content_filter"`               | `status: "incomplete"`                        | `stop_reason: "refusal"`    |
| `refusal`        | `finish_reason: "stop"` (recorded as `refusal`) | `status: "completed"` (recorded as `refusal`) | `stop_reason: "refusal"`    |

A rule's `finish` value overrides inferred and limit-triggered finish reasons, even when the events themselves would produce a different outcome.

#### Request limits

Request limits apply to both scripted and default replies.

| Limit          | Chat Completions                                   | Responses                                                                                      | Messages                                                                |
| -------------- | -------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Stop sequences | `stop` (ends with `stop`)                          | Not supported                                                                                  | `stop_sequences` (`stop_reason: "stop_sequence"`, sets `stop_sequence`) |
| Token cap      | `max_completion_tokens` or `max_tokens` (`length`) | `max_output_tokens` (`status: "incomplete"`, `incomplete_details.reason: "max_output_tokens"`) | `max_tokens` (`stop_reason: "max_tokens"`)                              |

- Stop sequences cut reply text at the first match and omit the matched sequence.
- Token caps estimate 1 token per 4 characters. Text past the cap is truncated, and a tool call that does not fit is dropped whole.

### Errors and faults

```yaml
ai:
  rules:
    - id: rate-limit-once
      match:
        textContains: "[retry]"
      times: 1
      error:
        status: 429
        message: Slow down.
        headers:
          retry-after: "1"

    - id: stall
      match:
        textContains: "[stall]"
        stream: true
      reply:
        - type: text
          text: partial answer
      fault:
        afterChunks: 2
        kind: stall
        stallMs: 30000
```

| Field                                     | Behavior                                                            |
| ----------------------------------------- | ------------------------------------------------------------------- |
| `error.status`                            | HTTP status from `400` to `599`                                     |
| `error.message`                           | Error message in the native error body                              |
| `error.type`, `error.code`, `error.param` | Optional native error fields                                        |
| `error.headers`                           | Response headers, such as `retry-after`                             |
| `fault.kind`                              | `stall` pauses the stream; `disconnect` cuts the connection         |
| `fault.afterChunks`                       | Content chunks (text or tool-argument deltas) sent before the fault |
| `fault.stallMs`                           | Stall duration in milliseconds                                      |

Fault rules require `match.stream: true`. The call record separates `fault` (`none`, `disconnect`, `stall`) from `delivery` (`pending`, `completed`, `client_aborted`, `error`).

### Variants

Use `variants` instead of `reply` to cycle through different responses across matching calls.

```yaml
ai:
  random:
    seed: 7
  rules:
    - id: flaky-answer
      match:
        textContains: flaky
      variants:
        - reply: [{ type: text, text: Complete answer. }]
        - reply: [{ type: text, text: Cut short. }]
          finish: length
        - reply: [{ type: text, text: Slow stream. }]
          timing: { ttftMs: 400, chunkDelayMs: 120 }
        - error: { status: 429, message: Slow down. }
```

- `ai.random.seed` shuffles each rule's variants into a cycle so every variant runs once before repeating. The same seed and match order always produce the same sequence, and a different seed changes the order.
- Each rule tracks its own match count since startup, reset, or `PUT /_ai/rules`, so other rules do not shift its sequence.
- Variants can hold `error` instead of `reply` and override rule-level `finish`, `timing`, and `fault`. SDK retries consume the next variant.

### Timing

- Replies are instant by default (`ttftMs: 0`, `chunkDelayMs: 0`).
- `ai.timing.ttftMs` delays the first byte of both unary and streamed replies. `ai.timing.chunkDelayMs` sets the delay between streamed frames and accepts either a number or a list applied in frame order, with the last value repeating.
- Pending timers cancel on client disconnect or reset. Streamed structured output splits only at JSON structural characters so a partial JSON parser can read values as they arrive.

## Defaults and strict mode

When no rule matches, the emulator returns a deterministic default:

| Request                  | Default reply                                       |
| ------------------------ | --------------------------------------------------- |
| Plain text               | Echoes the latest user text                         |
| Attachments only         | `Received N files (...)`                            |
| JSON mode without schema | `{}`                                                |
| JSON schema              | Deterministic, schema-valid object                  |
| Forced tool choice       | Tool call with arguments generated from tool schema |
| Tool result              | `Received the result of <tool or call id>.`         |

### Strict mode

Set `ai.strict: true` to fail every unmatched request with a 400 instead of returning a default. The error names the model and declared tools, and prints the missing rule as YAML and as a JSON body for `PUT /_ai/rules`.

### Schema validation and generation

On Chat Completions (`response_format`) and Responses (`text.format`), models starting with `claude` (with or without a prefix such as `anthropic/`) use Anthropic schema rules, and all other models use OpenAI rules; errors keep the route's error envelope. On Messages, `output_config.format` and strict tools always use Anthropic schema rules regardless of model.

| Dialect                 | Required shape                                                                                                                                                     | Rejected keywords                                                                                    |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- |
| OpenAI (`strict: true`) | Objects require `additionalProperties: false` and every property in `required`                                                                                     | `allOf`, `not`, `dependentRequired`, `dependentSchemas`, `if`, `then`, `else`                        |
| Anthropic               | On OpenAI routes, `response_format` requires `json_schema` with `strict: true` (`json_object` returns 400); on Messages, `output_config.format` uses `json_schema` | `oneOf`, numeric and string constraints, array constraints beyond `minItems` 0 or 1, external `$ref` |

Non-strict OpenAI schemas skip validation. Strict response schemas return `param: "response_format"` on Chat Completions or `param: "text.format"` on Responses, while strict function tools return `Invalid schema for function '<name>'` with `code: "invalid_function_parameters"`:

```json
{
  "error": {
    "message": "Invalid schema for response_format 'trip': In context=('properties', 'trip'), 'allOf' is not permitted.",
    "type": "invalid_request_error",
    "param": "response_format",
    "code": null
  }
}
```

Default schema generation supports a bounded subset:

- Supported keywords: `type`, `properties`, `required`, `enum`, `const`, `items`, numeric and length bounds, `nullable`, `anyOf` (first valid branch), `oneOf` (first branch whose sample matches only one branch; returns a native 400 if none does), common string `format` values, and local `$ref`. Sibling keywords alongside `$ref`, `anyOf`, or `oneOf` apply too.
- `pattern` generates only when paired with a known `format`; otherwise the request returns 400 asking for an explicit rule. Format samples, `enum`, or `const` values that fail `pattern` also return 400, and regex checks run under a time limit.
- Unsupported keywords return a 400 naming the schema path.

## State

### Stored responses

Responses are stored by default (up to the 1000 most recent; older ones are evicted) so multi-turn sessions resolve `previous_response_id` and `item_reference` inputs before rules run. Both `@ai-sdk/openai` 3.x (item references) and 4.x (inline tool history) work.

- An unknown id continues with empty context and records an unresolved reference.
- A function call with no matching `function_call_output` returns OpenAI's 400 (`No tool output found for function call <id>.`) unless its referenced history is missing.
- `store: false` skips storage, so later lookups return 404 while the call is still recorded.
- `DELETE` returns the native deleted object; a second delete returns 404. Reset clears stored responses.

### Control routes

| Method   | Path         | Behavior                                                                                        |
| -------- | ------------ | ----------------------------------------------------------------------------------------------- |
| `GET`    | `/_ai/calls` | Recorded calls as a JSON array, oldest first                                                    |
| `DELETE` | `/_ai/calls` | Clear calls; returns `{ "deleted": n }`                                                         |
| `GET`    | `/_ai/rules` | Active config (`rules` with `remaining`, `strict`, `timing`, `random`, `models`)                |
| `PUT`    | `/_ai/rules` | Replace runtime config; returns the same shape as `GET`                                         |
| `POST`   | `/_ai/reset` | Restore seeded rules and budgets, clear calls and stored responses; returns `{ "reset": true }` |

```bash
curl http://localhost:4014/_ai/rules > rules.json
curl -X PUT http://localhost:4014/_ai/rules \
  -H 'content-type: application/json' --data @rules.json
```

- `PUT /_ai/rules` replaces the full config (`rules`, `strict`, `timing`, `random`, `models`), resetting omitted fields to defaults and restoring every rule's full `times` budget.
- `remaining` (`null` for unlimited), `port`, and `baseUrl` are ignored on `PUT`.
- Invalid bodies return 400 with the failing path and leave previous rules active. Runtime changes never touch the seed file.

### Access

- Control routes and the inspector allow requests with no `Origin` (curl, tests) and same-origin requests; other origins get 403.
- Data routes allow requests with no `Origin`, same-origin requests, and loopback browser origins (`localhost`, `*.localhost`, `127.0.0.1`, `[::1]`); foreign browser origins get 403.
- Host-header validation allows only loopback names, IP addresses, and the configured base URL host to block DNS rebinding. Pass `--base-url http://<host>:<port>` for other hosts (such as Docker service names), or set `publicUrl` in `createEmulateHandler`.
- Startup warns when listening beyond loopback.

### Inspector and call record

Open `http://localhost:4014/` for read-only Calls and Rules tabs.

- The call record retains the last 500 generation requests with format, path, model, normalized messages, tools, references, `matched`, reply summary, status, fault, and delivery.
- `matched` is `{ id, remaining, rule }` for a rule, `{ default }` for a default, or `null` for a strict-mode miss.
- Prompts and tool arguments are recorded. API keys, auth headers, URL credentials, and file bytes are stripped; attachments keep only name, media type, size, and SHA-256.

## Limits

- `@ai-sdk/openai` cannot parse native refusal parts. Script refusal text as `text`, or test native refusals with the `openai` SDK.
- Chat Completions carries no reasoning text field; usage reports only `reasoning_tokens`, and OpenRouter's `reasoning` extensions are ignored.
- Attachments are input only: the emulator does not fetch remote files or use file contents to generate replies (inline bytes are decoded only to compute size and SHA-256). Chat Completions accepts only PDF files (no file URLs), and `@ai-sdk/openai` sends only images and PDFs unless `passThroughUnsupportedFiles` is set.
- Unsupported OpenAI features return a native 400 naming the feature: hosted tools, custom tools, allowed tool choice, background mode, Conversations API, multiple candidates (`n > 1`), audio input or output, and legacy `functions`.
- Unimplemented endpoints return a native 404 naming the supported paths: Gemini, embeddings, image generation, file uploads, input item listing, token counting, and response cancellation.
- Unknown optional fields are ignored, reply text uses no templating, and token usage numbers are deterministic estimates.
- An unknown key in the `ai` seed block fails startup with its path. See [Configuration](/docs/configuration).
